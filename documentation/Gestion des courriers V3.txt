\# 2. ENREGISTREMENT D'UN COURRIER D'ARRIVÉE



L'enregistrement d'un courrier d'arrivée doit être réalisé à travers une interface simple, moderne et structurée en plusieurs étapes.



L'objectif est que l'utilisateur puisse enregistrer complètement le courrier dans un parcours unique.



\## Étape 1 — Informations du courrier



L'utilisateur saisit les informations nécessaires concernant le courrier.



Exemples :



\* référence du courrier ;

\* date du courrier ;

\* date de réception ;

\* expéditeur ;

\* objet ;

\* type de courrier ;

\* niveau de priorité ;

\* niveau de confidentialité ;

\* autres métadonnées nécessaires.



Analyse le document Word pour déterminer les champs réellement nécessaires et ceux qui existent déjà dans l'application.



\### IMPORTANT



Lors de l'enregistrement initial du courrier d'arrivée, \*\*il ne faut pas demander à l'utilisateur de sélectionner :\*\*



\* l'entité chargée du traitement ;

\* le service chargé du traitement ;

\* le bureau chargé du traitement ;

\* l'agent destinataire.



Ces informations ne doivent pas faire partie de la saisie initiale.



L'imputation et l'affectation doivent intervenir \*\*après l'enregistrement\*\*, conformément au workflow configuré.



\---



\# 3. Étape 2 — Ajout des pièces jointes



La deuxième étape doit permettre d'ajouter les documents associés au courrier.



Prévoir notamment :



\* document principal ;

\* pièces jointes ;

\* plusieurs fichiers ;

\* possibilité de visualiser les fichiers ;

\* suppression/remplacement avant validation ;

\* métadonnées des documents si nécessaire.



Cette fonctionnalité doit être cohérente avec le fonctionnement de la \*\*GED du SIM\*\*.



Analyse l'existant avant de créer un nouveau mécanisme de gestion documentaire.



\---



\# 4. Étape 3 — Récapitulatif et validation



Avant l'enregistrement définitif, afficher une page de synthèse permettant à l'utilisateur de vérifier :



\* les informations du courrier ;

\* les pièces jointes ;

\* les métadonnées ;

\* les éventuelles informations complémentaires.



L'utilisateur doit pouvoir revenir aux étapes précédentes pour effectuer une correction.



Cette étape doit comporter une action claire :



\*\*Valider l'enregistrement\*\*



\---



\# 5. Étape 4 — Confirmation de l'enregistrement



Après validation :



\* enregistrer définitivement le courrier ;

\* générer son numéro/référence conformément aux règles définies ;

\* créer l'historique ;

\* déclencher le workflow configuré ;

\* déclencher les notifications nécessaires ;

\* afficher une confirmation à l'utilisateur.



Après confirmation, proposer :



\*\*Imprimer la fiche d'exploitation du courrier\*\*



La fiche d'exploitation doit également être accessible ultérieurement depuis le dossier du courrier.



Analyse le document Word afin de déterminer le contenu attendu de cette fiche.

\# 6. DESTINATAIRE DES COURRIERS D'ARRIVÉE — PARAMÉTRAGE



Actuellement, tout courrier arrivé est directement envoyé au \*\*DG\*\*.



Ce comportement ne doit plus être codé en dur.



Il doit devenir un \*\*paramètre du module Administration\*\*.



L'administrateur doit pouvoir définir l'entité qui reçoit automatiquement les courriers après leur enregistrement.



Exemples :



\* Direction Générale ;

\* Secrétariat Général ;

\* Cabinet ;

\* Bureau Courrier ;

\* autre entité de l'organisation.



Le système doit donc permettre de configurer :



> \*\*Entité destinataire initiale des courriers d'arrivée\*\*



Cette configuration doit être modifiable sans intervention dans le code.



\### Attention



Le destinataire initial doit être une configuration organisationnelle.



Il ne faut pas obligatoirement associer un courrier à un agent lors de son enregistrement.

\# 7. LISTE DES COURRIERS ET BANNETTES



La liste actuelle des courriers doit être analysée.



Je souhaite progressivement faire évoluer l'affichage vers un système de \*\*bannettes personnalisées selon le profil de l'utilisateur\*\*.



Les onglets génériques :



\* Entrant ;

\* Sortant ;

\* Interne ;



ne doivent plus être considérés comme l'organisation finale de l'interface.



Le document :



\*\*`guide user courriers SIM webdev.docx`\*\*



doit être analysé pour comprendre le concept de bannettes attendu.



\### IMPORTANT



Pour cette V3, ne développe pas encore toutes les règles complexes des bannettes si elles nécessitent une nouvelle conception.



Analyse d'abord le fonctionnement actuel et propose une architecture permettant d'introduire progressivement les bannettes.



Nous reviendrons ensuite en détail sur les règles de chaque bannette.

\# 8. NUMÉROTATION DES COURRIERS SORTANTS



Pour les courriers sortants, le numéro doit être généré automatiquement selon l'organisation et l'entité qui traite le courrier.



Exemple :



\*\*2026/DGDDI/DG/DIM/00002\*\*



Dans cet exemple :



\* `2026` = année ;

\* `DGDDI` = organisation ;

\* `DG` = niveau/entité concernée ;

\* `DIM` = entité ayant traité le courrier ;

\* `00002` = numéro séquentiel.



La partie correspondant à l'entité traitante doit donc être \*\*dynamique\*\*.



Elle ne doit pas être saisie manuellement par l'utilisateur.



Le système doit déterminer automatiquement le code de l'entité en fonction de l'entité ayant effectivement traité/validé le courrier selon le workflow.



\### À analyser



Détermine :



\* comment les codes des entités sont actuellement gérés ;

\* comment récupérer automatiquement le code de l'entité ;

\* comment gérer la séquence annuelle ;

\* comment éviter les doublons ;

\* comment gérer plusieurs entités ;

\* comment gérer les changements d'organisation ;

\* comment garantir l'intégrité de la numérotation.



Propose une architecture robuste avant implémentation.

\## Étape 1 — Informations du courrier



L'utilisateur saisit les informations nécessaires :

\* référence éventuelle ;

\* date ;

Analyse le document Word et l'existant afin de déterminer les champs pertinents.



\---



\## Étape 2 — Pièces jointes



Permettre de sélectionner ou ajouter les documents associés au courrier.



Le fonctionnement doit être cohérent avec la GED existante.



\---



\## Étape 3 — Destinataires



Cette étape doit permettre de définir les destinataires.



\### Destinataire principal



L'utilisateur doit pouvoir :



\* sélectionner un destinataire parmi les contacts existants ;

\* rechercher un contact ;

\* créer un nouveau contact si nécessaire.



\### Autres destinataires



Prévoir également :



\* ampliataires externes ;

\* ampliataires internes.



Le système doit clairement distinguer :



\* destinataire principal ;

\* ampliataires internes ;

\* ampliataires externes.



Analyse le modèle de données existant avant de créer de nouvelles structures.

\# 12. CONFIGURATION DES BANNETTES



À terme, le système doit pouvoir gérer les bannettes suivantes :



1\. \*\*COURRIERS À TRAITER\*\*

2\. \*\*COURRIERS EN COURS\*\*

3\. \*\*COURRIERS EN RETARD\*\*

4\. \*\*COURRIERS SORTANTS\*\*

5\. \*\*COURRIERS TRAITÉS\*\*

6\. \*\*COURRIERS ARCHIVÉS\*\*



Cependant, ces bannettes doivent être conçues comme un mécanisme \*\*dynamique et paramétrable\*\*, et non simplement comme six onglets statiques.



Le système devra être capable de déterminer automatiquement quels courriers apparaissent dans chaque bannette selon :



\* le profil de l'utilisateur ;

\* son rôle ;

\* son entité ;

\* son niveau hiérarchique ;

\* le workflow ;

\* le statut du courrier ;

\* les délais ;

\* les responsabilités ;

\* les droits d'accès.



\### Exemple



Un agent doit voir dans :



\*\*COURRIERS À TRAITER\*\*



uniquement les courriers qui nécessitent effectivement une action de sa part.



Un responsable doit pouvoir voir les courriers nécessitant son intervention ou sa validation.



Un courrier dont le délai est dépassé doit automatiquement apparaître dans :



\*\*COURRIERS EN RETARD\*\*



Un courrier terminé doit apparaître dans :



\*\*COURRIERS TRAITÉS\*\*



Et un courrier clôturé et archivé dans :



\*\*COURRIERS ARCHIVÉS\*\*
