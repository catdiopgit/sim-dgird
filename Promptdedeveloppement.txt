# Prompt de développement — Application SIM complète avec React JS, Supabase et PostgreSQL

Je souhaite développer une **application web complète, professionnelle, moderne et fonctionnelle de type SIM (Système d’Information Managérial)** en utilisant **React JS** pour le frontend et **Supabase / PostgreSQL** pour la base de données.

L’objectif n’est pas de créer une simple maquette ou une démonstration, mais une **application réellement fonctionnelle**, avec une architecture propre, évolutive, sécurisée et facilement maintenable.

## 1. Objectif général

Développer un SIM permettant de centraliser et gérer plusieurs processus métiers d’une organisation :

* Gestion des courriers
* GED — Gestion Électronique des Documents
* Gestion des projets
* Gestion des missions
* Gestion des utilisateurs et des droits
* Paramétrage général de l’application
* Tableau de bord et reporting

L’application doit être conçue de manière **modulaire**, afin de permettre l’activation, la désactivation et le paramétrage des différents modules selon les besoins de chaque organisation.

---

# 2. Technologies imposées

Utiliser les technologies suivantes :

### Frontend

* React JS
* TypeScript
* Vite
* React Router
* Une bibliothèque UI moderne et professionnelle, par exemple Material UI, Ant Design ou équivalent
* React Query / TanStack Query pour la gestion des données distantes
* Formulaires avec validation robuste
* Architecture composants réutilisables

### Backend / Base de données

Utiliser :

* Supabase
* PostgreSQL
* Supabase Auth pour l'authentification
* Supabase Storage pour le stockage des documents
* Row Level Security (RLS) pour sécuriser les données
* Supabase Edge Functions lorsque cela est nécessaire

Ne pas créer un backend inutilement complexe si les fonctionnalités de Supabase permettent de répondre au besoin.

# 5. Workflow des courriers

Le module courrier doit fonctionner selon un **workflow configurable**.

Le workflow doit permettre par exemple :

```text
Création
   ↓
Enregistrement
   ↓
Affectation
   ↓
Traitement
   ↓
Validation
   ↓
Signature
   ↓
Transmission
   ↓
Clôture
   ↓
Archivage
```

Cependant, ce workflow ne doit pas être codé en dur.

Il doit être **paramétrable par l'administrateur**.

L'administrateur doit pouvoir définir :

* Les étapes
* Les statuts
* Les transitions
* Les acteurs
* Les rôles autorisés
* Les délais
* Les notifications
* Les règles d'affectation

Chaque action doit être historisée.

# 25. Méthode de développement

Ne pas essayer de générer toute l'application en une seule étape.

Commencer par :

### Phase 1 — Initialisation

* Création du projet React + TypeScript + Vite
* Configuration de Supabase
* Configuration de l'architecture
* Configuration UI
* Authentification

### Phase 2 — Base de données

* Modèle de données
* Migrations
* Relations
* RLS
* Données initiales

### Phase 3 — Administration

* Organisation
* Utilisateurs
* Rôles
* Permissions
* Paramétrage

### Phase 4 — Courriers

Développer entièrement le module Courriers et son workflow.

### Phase 5 — GED

Développer entièrement le module GED et le workflow de versement/validation/classement.

### Phase 6 — Projets

Développer le suivi complet des projets et livrables.

### Phase 7 — Missions

Développer le module Missions avec le workflow défini précédemment.

### Phase 8 — Dashboard

Créer les tableaux de bord et indicateurs.

### Phase 9 — Sécurité et audit

Finaliser les RLS, permissions et journaux d'audit.

### Phase 10 — Tests et finalisation

Tester toutes les fonctionnalités, corriger les erreurs et préparer le déploiement.
